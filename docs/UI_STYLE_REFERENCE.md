# Prophet UI 样式参考

> 状态：设计基线，供后续重构实现使用；当前文档不代表界面已经写入项目。
>
> 参考来源：小红书工作台页面的配色、卡片密度与工作台气质。只借鉴视觉风格，不做逐像素复制，也不增加 Prophet 目前没有的功能。

## 1. 设计定位

Prophet 是一个本地运行的桌面效率工具，不是营销网站。界面应让用户感到安静、可信、信息充足，同时能快速完成长流程任务。

| 维度 | 定义 |
| --- | --- |
| 主页面类型 | 本地桌面工作台 / B 端工具 |
| 次页面类型 | 记录详情、分步表单、任务结果页 |
| 信息密度 | 中高密度，但通过卡片和留白分组 |
| 视觉气质 | 清爽、柔和、理性、轻微科技感 |
| 动效强度 | 很低，只用于状态反馈和层级切换 |
| 核心原则 | 现有功能优先、证据可追溯、状态可感知 |

关键词：`深蓝侧栏`、`浅蓝紫背景`、`白色圆角卡片`、`柔和状态色`、`紧凑间距`、`低干扰动效`。

## 2. 整体结构

```text
┌──────────────┬────────────────────────────────────────────┐
│ 品牌与主导航 │ 顶部标题 / 当前对象 / 页面操作              │
│              ├────────────────────────────────────────────┤
│ 人物画像     │                                            │
│ 聊天导出     │ 页面内容：列表、表单、卡片、任务或结果       │
│ 聊天分析     │                                            │
│ 赛博算命     │                                            │
│              │                                            │
│ 连接与数据状态│                                            │
└──────────────┴────────────────────────────────────────────┘
```

- 设计基准窗口：`1100 × 760 px`。
- 最小窗口：`820 × 600 px`；宽度不足时优先压缩内容区列数，不隐藏核心操作。
- 侧栏：基准宽度 `176–194 px`，固定在左侧。
- 顶栏：高度 `58 px`，只放页面标题、当前对象和真正可用的操作。
- 内容区：外边距 `22 px`，卡片间距 `10–12 px`。
- 页面滚动发生在内容区，侧栏和顶栏保持稳定。

## 3. 色彩与基础变量

```css
:root {
  --nav-deep: #1644b4;
  --nav-bright: #3f68ed;
  --canvas: #edf2ff;
  --surface: #ffffff;
  --ink: #182135;
  --muted: #7e899f;
  --line: #e7ebf4;
  --blue: #4e7ff2;
  --mint: #31cbb2;
  --violet: #7a67ee;
  --amber: #ffad4d;
  --cyan: #47c6df;
  --rose: #ff6f88;
  --radius: 12px;
  --shadow: 0 8px 24px rgba(65, 86, 139, 0.08);
  --motion: 140ms;
  --ease: cubic-bezier(0.2, 0.8, 0.2, 1);
}
```

### 用色规则

- 深蓝渐变只用于侧栏、品牌区和极少数强调区域。
- 主内容背景统一为浅蓝紫，白卡片负责承载信息。
- `--blue` 是唯一主操作色；不要在同一视图中出现多个竞争性的高饱和按钮。
- 薄荷绿表示成功或已完成，琥珀色表示等待或注意，玫红色表示失败或高风险。
- 紫、青等辅助色只用于分类标签、图标底色和轻量数据区分，不能替代状态语义。
- 正文与背景应保持清晰对比；浅色只用于背景，不用于小号正文。

## 4. 字体、圆角与间距

### 字体

```text
Inter, "Segoe UI Variable", "Microsoft YaHei UI", system-ui, sans-serif
```

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 20–22 / 30 px | 650–700 |
| 卡片标题 | 15–16 / 24 px | 600–650 |
| 正文 | 13–14 / 21 px | 400–500 |
| 辅助说明 | 12 / 18 px | 400–500 |
| 数字或状态值 | 14–18 / 24 px | 600–700 |

### 间距

采用 `4 px` 基础网格：`4 / 8 / 12 / 16 / 20 / 24 / 32`。

- 卡片内边距：普通卡片 `16 px`，信息密集卡片可降至 `12 px`。
- 表单字段间距：`12 px`；字段标签与控件间距：`6 px`。
- 标题与内容间距：`12–16 px`。
- 相关元素靠近，不相关区块通过卡片或至少 `20 px` 间距分开。

### 形状

- 主卡片圆角：`12 px`。
- 输入框、按钮、标签页圆角：`8–10 px`。
- 胶囊标签只用于状态和短分类，不把所有按钮都做成药丸形。
- 阴影保持轻微；表格、表单内层优先使用边框而不是叠加阴影。

## 5. 核心组件

### 5.1 左侧导航

- 背景使用 `--nav-deep` 到 `--nav-bright` 的纵向或轻微斜向渐变。
- 顶部保留 Prophet 品牌标识和简短产品名。
- 主导航仅保留四项：人物画像、聊天导出、聊天分析、赛博算命。
- 每项由统一风格的 `18–20 px` SVG 图标和文字构成，不使用 Emoji。
- 当前项使用半透明白色底、白色文字和轻微内高光；其他项降低到约 75% 不透明度。
- 底部显示真实状态，例如“模型已连接”“2 个本地数据库”；不能伪造在线状态或统计数字。

### 5.2 顶栏

- 左侧显示当前页面标题，可附一行短说明或当前人物。
- 右侧只放真实可用操作，例如“设置”“导入”“新建任务”。
- 不添加尚未实现的全局搜索、通知铃铛、头像菜单或仪表盘入口。
- 顶栏与内容区可用一条 `--line` 分隔，不使用重阴影。

### 5.3 卡片

- 白色背景、`1 px` 浅边框、`12 px` 圆角、轻阴影。
- 卡片标题、摘要、操作三者层级明确；操作区尽量固定在右上或底部。
- 可点击卡片必须有悬停、键盘焦点和按下状态。
- 证据、置信度、来源、时间等信息不能只靠颜色表达。

### 5.4 按钮

| 类型 | 用途 | 样式 |
| --- | --- | --- |
| 主按钮 | 页面唯一主推进动作 | 蓝底白字 |
| 次按钮 | 保存、导入、查看等普通动作 | 白底蓝字、浅边框 |
| 文字按钮 | 低优先级局部动作 | 透明背景、蓝色文字 |
| 危险按钮 | 删除、清空、覆盖 | 默认克制，确认后使用玫红强调 |

- 常规高度 `36–40 px`，最小点击区域不低于 `40 × 40 px`。
- 按钮文案使用动作词，如“开始分析”“保存画像”，避免含糊的“确定”。
- 运行中的按钮显示进度语义并阻止重复提交。

### 5.5 表单

- 标签始终可见，不以占位文字代替标签。
- 文本输入、下拉框、日期与文件选择使用统一高度和边框。
- 原生 HTML 控件能满足需求时优先使用原生控件。
- 错误提示紧邻字段，说明问题及修正方式。
- 长流程按“输入 → 确认 → 运行 → 结果”分区，不把全部字段堆成一张大表单。

### 5.6 标签页与筛选

- 标签页使用白色或透明底，激活项以蓝色文字和细底线/浅蓝底表示。
- 人物画像固定标签：当前画像、添加材料、预测与复盘、历史与导出。
- 标签数量较多时允许水平滚动，不把文字压缩到不可读。
- 筛选项与结果数量相邻，清除筛选入口保持可见。

### 5.7 状态与进度

- 统一状态：未开始、运行中、已完成、失败、已取消。
- 长任务显示当前步骤、简短说明和进度；没有可信百分比时使用不定进度条。
- 失败卡片保留错误摘要、重试入口和必要日志位置，不直接清空用户输入。
- Toast 只用于短暂确认；需要用户处理的信息必须留在页面中。

## 6. 四个功能页的套用方式

### 6.1 人物画像

采用“左侧对象与材料、右侧详情”的双栏结构。

- 左栏：人物搜索/选择、人物列表、材料数量、添加人物。
- 右栏顶部：人物名称、最后更新时间、设置或导出操作。
- 右栏标签：当前画像、添加材料、预测与复盘、历史与导出。
- 当前画像：先显示摘要，再用彩色但克制的特质卡展示结论、置信度和证据数量。
- 证据列表明确显示来源、时间、材料片段；点击后能定位上下文。
- 添加材料按输入方式分组，分析前显示材料预览和目标人物。

### 6.2 聊天导出

采用“引导表单 + 任务状态 + 结果”的单主线布局。

1. 选择 QQ 或微信及本地数据来源。
2. 选择会话、时间范围和导出格式。
3. 选择保存目录并确认任务。
4. 显示运行状态、成功/失败数量和结果文件入口。

高级选项默认折叠；主路径应在一屏内看清。

### 6.3 聊天分析

采用“文件检查 → 分析模式 → 任务进度 → 报告结果”的流程。

- 文件区显示格式、记录数量、时间范围、参与者和异常提示。
- Agent、手动、一键三种模式使用并列选择卡，但同一时间只有一个主动作。
- 运行中持续保留输入摘要，防止用户忘记当前分析对象。
- 报告结果先展示结论摘要，再展示证据、细节和导出操作。

### 6.4 赛博算命

采用“输入面板 + 结果主区”的结构，避免神秘化装饰压过信息。

- 输入区清楚区分事实字段、可选字段和推演方式。
- 结果区先给摘要与边界说明，再展示各体系结果、依据和时间信息。
- 历史、复盘、人物、知识、导入导出通过标签页组织。
- 七种推演方式可以使用不同辅助色，但布局、按钮和结果层级保持一致。

## 7. 交互与动效

- 默认过渡：`140ms cubic-bezier(0.2, 0.8, 0.2, 1)`。
- 允许：颜色、边框、透明度、`2 px` 以内位移的状态过渡。
- 禁止：大面积弹跳、循环呼吸、背景粒子、无意义数字滚动和长时间页面入场动画。
- 弹窗只用于设置、确认危险操作和必须打断流程的选择；普通详情优先在页面内展开。
- 支持 `prefers-reduced-motion`，用户要求减少动态时关闭非必要动画。

## 8. 可访问性与易用性底线

- 键盘可以到达所有按钮、标签页、表单和列表项。
- 焦点环清晰可见，不能只依赖浏览器几乎看不见的默认样式。
- 图标按钮必须提供文字标签或 `aria-label`。
- 状态不能只靠颜色；同时使用文字或图标。
- 正文不低于 `12 px`，常规正文优先 `13–14 px`。
- 删除、覆盖数据库、清空历史等操作必须二次确认。
- API 密钥永远不回显完整值，也不进入前端日志。

## 9. 明确不采用的样式

- 不添加与真实功能无关的仪表盘数字、排行榜和趋势图。
- 不使用巨型欢迎横幅或营销式 Hero 区域。
- 不使用重度毛玻璃、霓虹描边、大面积渐变文字。
- 不让每张卡片使用不同颜色或不同圆角。
- 不用 Emoji 充当产品图标。
- 不隐藏证据、置信度、任务错误和数据来源。
- 不因追求“小红书感”而复制其内容社区布局；Prophet 的任务流优先。

## 10. 实现验收清单

- [ ] 四个主导航与现有功能一一对应，没有虚构入口。
- [ ] 颜色、字体、圆角、阴影和间距均来自本文基础变量。
- [ ] `1100 × 760 px` 下无需横向滚动即可完成主流程。
- [ ] `820 × 600 px` 下核心操作仍可见、可滚动、可点击。
- [ ] 人物画像的结论可以追溯到材料证据。
- [ ] 导出、分析和推演长任务都有运行、失败、取消和完成状态。
- [ ] 键盘焦点、控件标签、对比度和减少动效模式可用。
- [ ] 所有危险操作均有明确对象和二次确认。
- [ ] 界面中没有尚未实现的搜索、通知或统计数据。
