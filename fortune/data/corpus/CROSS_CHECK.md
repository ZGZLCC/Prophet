# 阶段 3 语料复核清单

## 范围

- `zhouyi.jsonl`：64 条卦名、64 条卦辞、384 条爻辞。
- `yizhuan.jsonl`：64 条彖传、64 条大象、384 条小象。
- 每条记录都有稳定 ID、传统/简体字段、固定分卷链接、影印页标识、权利声明、审核状态和 SHA-256 校验值。
- 生成器为 `scripts/build-corpus.mjs`；运行时不联网，直接读取本地 JSONL。

## 已记录的底本异文/排版情况

生成器只为“定位边界”使用有限的异体字等价映射，不改写输出的 `textTraditional`：

- 个别卦符与卦名不一致，卦号以正文卦名为准；
- `剝/剥`、`頤/頥`、`兌/兊`、`既/旣` 等字形按底本原样保存；
- 个别爻位使用影像字形（如初爻、九五），按上下文定位，不把影像字形静默替换进传统文本；
- 卷六第 62 卦的底本把彖传首标记排成第一处“象曰”，第二处才是大象；解析器已按连续文本和影印页结构分离，异常保留在本清单；
- 乾卦的爻辞、彖传和象传排版顺序特殊；`用九/用六` 不属于本阶段 384 条六爻主记录，因此未伪装成普通爻位。

## 校验与运行门槛

- 校验算法：对去掉 `checksum` 的记录做 Unicode NFC、LF 换行规范化和递归键排序后计算 `sha256:<64 位小写十六进制>`。
- `loadCorpus()` 默认要求 `reviewStatus >= double-checked`，校验失败或缺少来源会阻止加载。
- 检索按 `(hexagramNumber, section, line)` 精确匹配；Prompt 预算只丢弃完整段落，不截断古籍原文。

## 后续人工抽查建议

语料已具备可运行的来源闭环；若后续修改底本或生成器，应优先对 `sourcePage` 指向的影印页逐条复核，并重新生成校验值。任何未完成复核的记录必须标为 `single-checked` 或 `blocked`，不能继续使用 `double-checked`。
